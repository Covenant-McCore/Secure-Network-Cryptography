Compose Secure Message

What happens when you send

  1. Authorize — your role is verified server-side.
  2. Key establishment — ML-KEM-768 encapsulates a shared secret to the recipient's public key.
  3. Key derivation — HKDF-SHA-256 derives two independent session keys from the shared secret.
  4. Encryption — the subject and body are each sealed with AES-256-GCM, producing ciphertext + nonce + auth tag.
  5. Signature — you sign the ciphertext envelope with Ed25519 for authenticity and non-repudiation.
  6. Storage — only the sealed envelope reaches the database. Plaintext never leaves this browser tab.

The recipient will reverse the process: verify signature, decapsulate shared secret, derive keys, decrypt, and check the SHA-256 fingerprint.
